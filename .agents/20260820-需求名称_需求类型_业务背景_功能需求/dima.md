## D - 定义 (Define)

### 1.1 业务背景与痛点

| 维度 | 描述 |
|------|------|
| **当前现状** | 定时同步、数据统计、文件同步、营销活动、批处理任务全部写死在代码中 |
| **核心痛点** | 维护成本高、无法统一管理、缺少失败处理机制、难以监控和告警 |
| **业务价值** | 统一调度能力复用、降低开发成本、提升任务可观测性、保障任务执行可靠性 |

### 1.2 需求范围

| 功能模块 | 需求描述 | 优先级 |
|----------|----------|--------|
| **Cron 表达式支持** | 支持标准的 Cron 表达式配置，精确到秒级/分钟级调度 | P0 |
| **任务管理** | 任务的增删改查、启用/禁用、分类管理 | P0 |
| **失败重试** | 任务执行失败后自动重试，可配置重试次数和间隔策略 | P0 |
| **手动执行** | 支持手动触发任务立即执行，用于调试和应急 | P0 |
| **暂停/恢复** | 支持暂停正在运行的任务，以及恢复已暂停的任务 | P0 |
| **执行日志** | 记录每次任务执行的完整日志，包括开始时间、结束时间、状态、结果 | P0 |
| **告警通知** | 任务失败/超时等异常场景下，通过邮件/钉钉/企微等方式通知 | P1 |

### 1.3 成功标准

- 支持至少 1000 个定时任务的统一管理
- 任务调度延迟 ≤ 1 秒（在 Cron 精度范围内）
- 失败重试成功率 ≥ 99%（排除业务逻辑错误）
- 执行日志完整可追溯，保留至少 30 天

## I - 调研 (Investigate)

### 2.1 技术选型分析

| 方案 | 优势 | 劣势 | 推荐度 |
|------|------|------|--------|
| **XXL-JOB** | 轻量级、开箱即用、自带调度中心和执行器、支持分布式、有管理界面 | 依赖数据库、调度器单点风险（需高可用部署） | ⭐⭐⭐⭐⭐ |
| **Quartz** | 成熟稳定、灵活度高、与 Spring 深度集成 | 无管理界面、需自行开发调度中心、集群部署复杂 | ⭐⭐⭐⭐ |
| **Redis + MQ 自研** | 高度定制化、无外部依赖 | 开发成本高、需自行实现分布式锁、失败重试、日志等全套能力 | ⭐⭐⭐ |

### 2.2 推荐方案：XXL-JOB + Redis + MQ 混合架构

**推荐理由**：
- XXL-JOB 作为调度中心，提供成熟的 Cron 调度、失败重试、日志管理能力
- Redis 作为分布式锁和任务状态缓存，提升调度性能
- MQ（RocketMQ / RabbitMQ）作为异步消息通道，解耦任务分发与执行

### 2.3 竞品/行业方案调研

| 平台 | 特点 | 参考价值 |
|------|------|----------|
| **阿里 SchedulerX** | 企业级分布式调度，支持工作流编排 | 工作流编排设计、灰度发布策略 |
| **Apache Airflow** | DAG 工作流调度，生态丰富 | 任务依赖管理、DAG 设计理念 |
| **Elastic Job** | 分布式调度 + 分片处理 | 分片策略、任务资源隔离 |

### 3.2 核心组件设计

#### 3.2.1 调度中心 (Scheduler Service)

| 子模块 | 职责说明 |
|--------|----------|
| **任务管理** | 任务的 CRUD、启用/禁用、分类管理，提供 RESTful API |
| **Cron 调度** | 基于 Quartz/XXL-JOB 的 Cron 表达式解析与触发，支持秒级和分钟级 |
| **失败重试** | 指数退避重试策略，可配置最大重试次数（默认 3 次） |
| **告警服务** | 对接钉钉、企业微信、邮件等渠道，发送任务执行状态通知 |
| **执行日志** | 收集执行器上报的日志，提供日志查询和检索能力 |
| **注册中心** | 管理执行器实例的注册与心跳检测，实现动态上下线 |

#### 3.2.2 执行器 (Job Executor)

| 子模块 | 职责说明 |
|--------|----------|
| **任务执行** | 接收调度指令，执行具体业务逻辑 |
| **状态上报** | 实时上报任务执行状态（运行中/成功/失败） |
| **日志采集** | 采集执行过程中的日志，异步上报到调度中心 |
| **心跳保活** | 定时发送心跳，维持执行器注册状态 |

#### 3.2.3 消息队列 (MQ)

| 用途 | 说明 |
|------|------|
| **任务分发** | 调度中心将任务投递到 MQ，执行器消费执行 |
| **状态回调** | 执行器完成执行后将结果写入 MQ，调度中心消费更新状态 |
| **流量削峰** | 缓冲突发任务请求，保护执行器不被击穿 |

#### 3.2.4 Redis 缓存

| 用途 | 说明 |
|------|------|
| **任务锁** | 防止同一个任务在多个调度器被同时触发 |
| **任务状态缓存** | 缓存任务最新状态，减少数据库查询 |
| **分布式计数器** | 记录重试次数、执行次数等 |

### 4.2 跨仓库协作分工

| 仓库 | 职责 |
|------|------|
| **testDj-main** | 调度中心核心服务（Scheduler Service）、管理界面、API 网关 |
| **testDJnew-main** | 执行器 SDK（Job Executor）、通用任务库、插件生态 |

### 4.3 风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 调度器单点故障 | 全部任务无法调度 | 中 | 调度中心多节点部署 + 分布式锁 |
| 任务执行超时/雪崩 | 执行器资源耗尽 | 高 | 任务超时熔断、线程池隔离、限流 |
| 日志量过大 | 存储压力、查询缓慢 | 中 | 日志分表 + 归档策略、ES 全文检索 |
| Cron 精度不满足 | 秒级任务延迟 | 低 | 使用 Quartz 及内存调度提升精度 |
