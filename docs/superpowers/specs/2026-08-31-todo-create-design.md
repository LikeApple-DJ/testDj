# 待办事项「新增」功能设计

日期：2026-08-31
状态：已确认

## 1. 背景与目标

为内部用户提供一个轻量 Web 应用，用于记录日常待办事项。本期仅实现「新增」最小闭环：用户在页面填写事项名称和描述并提交，提交成功后页面展示已保存的待办列表作为创建反馈。不做编辑、删除、认证等扩展能力。

## 2. 需求摘要

| 项 | 内容 |
|---|---|
| 交付形态 | Web 应用（服务端渲染） |
| 核心功能 | 新增待办事项（仅创建） |
| 字段 | 事项名称（name）、描述（description） |
| 创建后反馈 | 成功提示 + 列表展示 |
| 数据存储 | 本地 JSON 文件 |
| 目标用户 | 内部用户 |
| 技术方案 | Flask + JSON 文件 |

## 3. 架构

- 单文件 Flask 应用（`app.py`），服务端渲染。
- 一个页面同时承载「录入表单」与「已保存列表」。
- 存储为本地 `todos.json` 文件：页面加载时读取，提交时追加并写回。

## 4. 数据模型

```json
{
  "id": 1,
  "name": "事项名称",
  "description": "事项描述",
  "created_at": "2026-08-31T10:00:00Z"
}
```

- `id`：整数，自增，初始为 1。
- `name`：字符串，必填，非空。
- `description`：字符串，可选（允许为空）。
- `created_at`：ISO 8601 时间戳，创建时由服务端生成。

顶层结构为 JSON 数组：`[{...}, {...}]`。

## 5. 组件与职责

| 组件 | 职责 |
|---|---|
| `app.py` | Flask 路由与业务逻辑：`GET /` 渲染表单+列表；`POST /todos` 处理创建。封装 JSON 文件读写、ID 自增、追加写入。 |
| `templates/index.html` | Jinja2 模板：表单（名称、描述、提交按钮）+ 列表区（按时间倒序展示已有事项）+ 成功/错误提示。 |
| `todos.json` | 数据文件；不存在时视为空列表。 |
| `requirements.txt` | 依赖声明：Flask。 |

## 6. 数据流

1. `GET /` → 读取 `todos.json`（缺失则空列表）→ 渲染表单与列表。
2. `POST /todos`（表单字段 name、description）→ 校验 name 非空 → 生成 id 与 created_at → 追加到列表 → 写回 `todos.json` → 重定向回 `GET /`。
3. 列表刷新后新事项可见，即「成功+列表展示」反馈。

## 7. 错误处理

- name 为空 → 不写入，重新渲染页面并显示错误提示。
- `todos.json` 读取失败或不存在 → 视为空列表，不影响页面加载。
- 写入失败 → 返回错误提示（内部场景接受简单反馈）。

## 8. 测试

- 冒烟：启动 Flask，`GET /` 返回 200 且页面含表单；`POST /todos` 提交后列表出现新事项、`todos.json` 含对应记录。
- 边界：空 name 提交被拦截并提示；`todos.json` 不存在时首次创建正常生成文件。

## 9. 范围裁剪（YAGNI）

明确不做：编辑、删除、用户认证、数据库、分页、前端框架。仅保留「创建」最小闭环 + 列表展示反馈。
